# UI polish validation

The 2026-10-03 follow-up updates regression coverage for the neutral UI foundation,
compact Source/Flow layouts, Watch context menus and exact breakpoint interactions.
It supersedes the earlier compile-only checkpoint notes in the feature pages.
Validation used JDK 25 and the isolated `ui-polish-pr` worktree based on main
`7020ff7fdbf89adb81178f7058c455ac8d8433bc`.

## Initial PR results

- **50 JVM tests passed:** 40 in `clientTest`, 10 in `test`; zero failures, errors
  or skipped tests in their XML reports. The final check reran `clientTest`;
  `test` reused its passing result because its inputs had not changed.
- **10 selected native client GameTest classes passed:** nine together, followed
  by the focused `DebuggerBreakpointUiGameTest` after updating its removed
  list/Undo expectations. No production code changed between those native runs.
- `compileClientJava`, `processResources` and `git diff --check` passed.

`DebuggerBreakpointUiGameTest` retains real server Save/Delete acknowledgements,
checks return to the same editor and cursor, preserves the separate whole-command
definition, and recreates the deleted exact stage through native keyboard input.
The navigation list assertions check both saved destinations remain present and
unavailable rows cannot send hidden edits.

The new `DebuggerNavigationTest` replaces widget instances during pending edits
and checks explicit Tab/click navigation wins over later acknowledgement or
rejection. `FlowBreakpointInteractionGameTest` drives actual screen events for
unset run/function markers, visual Tab order, wrapped-row reveal, pending focus,
direct exact-target editors, cancel without mutation and list navigation.

Source checks retain glyph/edge pixel comparisons for the authoritative amber
stop and require manual code selection to remain neutral. Marker visibility checks
use the shared neutral color, including modal dimming. Compact Watch checks use
row menus and the full right-aligned value hit area in English/Korean fixtures.

## CI follow-up

The first [PR #56 CI run](https://github.com/nutyworks/codon/actions/runs/37110663581)
on `adb985e425a79942f33df53e8ded1faddadcef8c` passed build and shard 7 but failed
seven native shards. Their logs and screenshots were downloaded to the adjacent
`pr56-ci-initial/client-game-test-evidence-*` directories; the combined failed-job
log is `pr56-ci-initial-failures.log`.

| Shard | First failing scenario | Diagnosis and retained coverage |
| --- | --- | --- |
| 1 | `DebuggerSourceIconGameTest` | The old focus-border expectation was obsolete. Check the actual flat toolbar style, neutral hover and white corner focus mark while retaining all glyph shape, scale and activation assertions. |
| 2 | `DebuggerTooltipGameTest` | The fixture still treated legacy stage zero as the line target. Updating it exposed a real missing whole-line tooltip. Restore localized condition/click/right-click hints and retain a separate stage count without aliasing the target. |
| 3 | `DebuggerWatchEditorGameTest` | Pin/Delete moved to row menus. Drive those menus with native input and retain exact-definition pin/delete checks. |
| 4 | `FlowLegacyConditionGameTest` | Removed footer control and summary-method lookups were obsolete. Check legacy/line isolation, the exact target's condition, pending gating, rejection feedback and editor Cancel. |
| 5 | `DebuggerWatchPinGameTest` | Inline pin controls moved to row menus. Retain real-server two-entity pinning, independent history, unpin merge and removed-entity behavior. |
| 6 | `DebuggerNbtTreeGameTest` | The heading and field-action icon changed. Past those stale lookups, the compact inspector exposed a real regression: the taller Flow detail band left only an NBT heading. Allocate a compact Contexts row so NBT data remains visible; retain source identity, transport, expansion and pin assertions. |
| 8 | `DebuggerWatchGameTest` | Inline Edit moved to the row menu. Retain the real watch reads and open the selected row's editor through its menu. |

The same old NBT field icon lookup was corrected in
`DebuggerNbtPendingButtonsGameTest`; pending-input guards remain asserted.
The missing `flite` warning also appears in passing shard 7. The observed failures
were explicit UI assertions/exceptions, not display startup or environment failures.
The compact NBT screenshot, restored English Source gutter tooltip and initial
Source icon failure screenshot were visually inspected in addition to the native
assertions and logs. Final NBT/tooltip captures are preserved beside the checkout
in `pr56-final-evidence/`.

The broader run also reached an obsolete assertion in
`DebuggerPresentationGameTest`: stopped Flow clauses no longer carry a pause
icon. The replacement requires amber on every wrapped fragment and preserves the
continuation-width check. Group-member selection now scrolls the smaller Contexts
viewport when needed, while still checking that scrolling does not select a row
and Enter cannot activate a scrolled-out control.

The Watch editor fixture now carries an explicit synthetic pause ID so Pin can
actually execute. Its assertion compares the complete before/after definition
set for a known nonconflicting watch, rather than passing because a different
fixture watch was already pinned. This remains client presentation coverage.

The full run exposed an order-dependent Peek fixture issue. Its injected EditBox
had no mouse hit target, and the native right-click could land on a Flow clause
under a previous test's cursor. A focused diagnostic deliberately positioned the
cursor there and reproduced the unexpected `DebuggerContextMenu` intercepting the
later menu key (`pr56-peek-clause-diagnose.log`). The fixture now positions the
cursor in a blank corner for that guard, asserts no unrelated modal opened, and
asserts the hide gesture is active before closing. Menu close, visibility reset,
pause/selection preservation and reconnect assertions remain unchanged.
